# OPENHTPC Update Runtime Regeneration — Dev14

Baseline: `1.1.3-dev13`, `optical-tmdb-search-recovery-ux-dev13`, commit
`72cb40f`.

Dev14 closes the public RC3 update gap. Update mode previously preserved the
Hardware Passport and refreshed canonical capabilities, but retained runtime and
MPV files generated by the installed older release. The updater now installs the
current payload, refreshes canonical capabilities exactly once, and invokes the
same authoritative generator used by the fresh Builder.

The valid Hardware Passport and persistent user-owned data remain preserved:
user configuration, MEDIA sources, synthetic TMDb credential, confirmed disc
associations, audio preference, and intentional cache/state. Version-derived
PURE/REFERENCE configuration and runtime provenance are atomically replaced.

If Passport validation, capability refresh, runtime generation, or READY
validation fails, the installer exits unsuccessfully. A NOT_READY generation
persists its diagnostic pending state only after stale READY runtime files have
been made unavailable; persistent user data is not removed.

The bounded public-RC3 fixture stages only the real updater/installer entry
points, Builder, runtime generator, payload metadata, managed manifest, and
synthetic state. It proves stale RC3 markers are replaced by Dev14 provenance and
current policy, and proves preservation and repeat-update safety from resulting
filesystem state.
